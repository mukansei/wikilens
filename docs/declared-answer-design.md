# 모델이 답을 진술하면 — 연관 간선 설계안

**제안이지 결정이 아니다.** 아래 수치는 전부 실측이고, 마지막 절의 "먼저 잴 것" 을
안 하고 만들면 오늘 겪은 실패를 되풀이한다(`docs/experiment-2026-08-14-learning.md`:
설계 전제가 틀려 처치의 효과가 나타날 자리가 없었다).

---

## 무엇이 문제인가 — 셋이고, 성질이 다르다

### ① `dest` 가 추정이다

```kotlin
dest = span.reads.lastOrNull()      // 마지막으로 읽은 것이 답이라고 가정
```

`CLAUDE.md` 가 이미 **남은 약점**으로 적어뒀다. 그런데 **이 추정의 오류율은 측정된 적이
없다.** 얼마나 자주 틀리는지 모르는 채로 그 위에 세 가지가 얹혀 있다:

```
postings[항][dest] += 가중       간선 자체
passedOver = reads - {dest}      미스 대상
rank = ranked.indexOf(dest)      깊이 가중 (1위 ×1 · 2~3위 ×2 · 그 아래 ×3)
```

### ② 문서의 97%에 앵커가 없다

| 인링크 | 문서 | |
|---:|---:|---|
| 0 | 13,469 | **97%** — 별칭 칸이 `(별칭 없음)` |
| 1 | 227 | 2% |
| 2+ | 237 | 2% |

`CLAUDE.md` 는 "고아 88%" 로 적혀 있는데 이 코퍼스 실측은 **97%** 다. 앵커 층이 닿는
문서가 464건뿐이다.

### ③ 표현이 바뀌면 전이가 안 된다

서빙 조건이 `ebLower × 커버리지 ≥ 0.45` 이고, **커버리지는 항 겹침 비율**이다. 그룹 안
세 표현의 항 겹침이 0~3개(질의 항 4~8개)라 `c = 0.17~0.43` 으로 문턱 `0.73` 에 못 미친다.

**같은 신호를 grep 으로 매칭하면 전이가 된다** — 문턱이 없어 한 낱말만 걸려도 그 줄이
나온다. `q0` 로 남긴 줄을 `q1`·`q2` 로 찾아보면:

```
G01  주문 걸림 · 제품명 없음        1/2
G02  없음 · 없음                   0/2
G03  공유 걸림 · 공유하기 걸림       2/2
G04  사업자 걸림 · 사업자 걸림       2/2
```

**서버판 전이는 0/8 이었는데 grep 은 5/8 이다.** 신호가 아니라 **소비 방식**이 갈랐다.

## 두 신호는 성질이 다르다 — 여기가 설계의 갈림길

| | 확률적 신호 (지금의 학습층) | 서술적 신호 (앵커) |
|---|---|---|
| 답하는 것 | 이 항으로 물으면 이 문서가 답이었나 | 이 문서를 뭐라고 부르나 |
| 유용해지는 시점 | 관측이 문턱을 넘을 때 | **1회로 충분** |
| 강등 | 미스로 내려간다 | **기전 없음** |
| 반영 | 즉시 | 재색인 시 |
| 매칭 | EB × 커버리지 | BM25 (부스트 4.0) |

**모델의 진술은 둘 다에 해당한다.** "이 질의의 답은 X" 는

- "이 항들 → X" (확률적, 반복이 필요)
- "X 를 이렇게 부를 수 있다" (서술적, 1회로 유용)

둘째 해석이 강하고, **측정된 공백(97% 앵커 0)이 정확히 앵커 공백**이다.

## 제안 — 진술 하나가 두 경로를 먹인다

```
POST /api/answer {sessionId, pageId}      새 엔드포인트 · MCP 5번째 도구
```

### 경로 1 — 즉시: `dest` 를 진술로 확정

```
Span.declaredDest 가 있으면 그것, 없으면 reads.last()
```

**폴백이 필수다.** 모델이 안 부르면 지금 동작 그대로여야 한다 — 그래야 되돌릴 수 있고,
안 부른 세션도 안 버린다. 그리고 **안 부른 비율을 센다**(`/api/stats`) — 스킬 지시가
먹히는지가 그 값으로만 보인다.

따라오는 개선 둘:

- `passedOver` 가 정확해진다. 지금은 "마지막 아닌 것 = 지나침" 인데, 진짜 답을 알면
  중간에 읽은 정답도 지나침으로 안 센다.
- `rank` 가중이 맞아진다. "깊은 데서 건졌나" 가 `dest` 순위에 걸려 있다.

### 경로 2 — 재색인 시: 학습된 앵커

궤적 로그의 `(keywords, dest)` 를 모아 **별도 필드**로 색인한다.

```
Fields.LEARNED_ANCHOR   부스트 2.0
                        (사람 앵커 4.0 · 제목 3.0 · 본문 1.0 사이)
```

**별도 필드인 이유 셋:**

1. **사람 앵커를 못 이긴다.** 4.0 > 2.0 이라 진짜 앵커가 있으면 그쪽이 이긴다.
2. **되돌릴 수 있다.** 필드를 안 채우고 재색인하면 그대로 사라진다.
3. **사람 신호와 안 섞인다.** `CLAUDE.md` 의 "사람 링크와 기계 링크가 섞이면 정답
   신호가 영구히 오염된다" 와 같은 형태다. 섞지 않으면 그 규칙을 안 깬다.

**이 경로가 ③(전이)을 푼다.** BM25 는 커버리지 문턱이 없어 항 하나만 겹쳐도 점수가 붙는다.

## 데이터는 이미 있다 — 스키마 변경이 필요 없다

`trajectories.jsonl` 이 이미 `keywords` 와 `dest` 를 담는다:

```json
{"ts":…,"session":"mcp-…","keywords":["<시스템>","batch","실행","주기"],
 "kind":"LOCALIZATION","reads":["312282188"],"dest":"312282188", …}
```

**원문 질의는 안 남지만 그게 오히려 낫다.** 앵커로 쓸 것은 분석기가 남긴 항이고,
원문의 군더더기(`어떻게`·`있나`)는 어차피 버려야 한다. `keywords` 를 공백으로 이어
`LEARNED_ANCHOR` 에 넣으면 된다.

**쓸 자리도 이미 있다.** 볼트는 `:ro` 로 마운트된다(`compose.yml`) — 서버는 볼트에
못 쓴다. 그리고 쓸 필요도 없다. 궤적 로그가 이미 정본이고 재색인 때 재생된다.

```
vault   :ro          쓰기 불가. 미러는 순수하게 유지된다
state   쓰기 가능     trajectories.jsonl — 이미 정본
index   쓰기 가능     재색인으로 복구 가능
```

## 위험

### 강등 기전이 없다 (경로 2)

틀린 학습 앵커가 부스트 2.0 으로 색인에 남는다. 학습층은 미스로 내려가지만 앵커는 아니다.

**완화 셋:**

- 부스트를 낮게(2.0) 두어 사람 앵커·제목을 못 이기게 한다.
- 재색인마다 궤적 로그에서 다시 만든다 — 로그에서 걷어내면 사라진다.
- **서빙 문턱을 앵커에도 건다**: 궤적이 N회 이상인 `(항, dest)` 쌍만 앵커가 된다.
  N=1 이면 "1회로 유용" 이라는 서술적 성질을 살리고, N=2 이상이면 안전을 산다.
  **이 값은 측정해서 정할 것** — 지금 고르면 근거 없는 상수가 하나 는다.

### 게이트와의 관계가 미정이다

계약이 `LOCALIZATION만 간선 생성` 인데, 실측하면 **게이트가 항등함수다**:

```
byKind: LOCALIZATION 7 · TRACING 0 · RATIONALE 0 · UNKNOWN 0
```

모델이 "이게 답이다" 라고 하는데 게이트가 TRACING 으로 분류하면 간선이 안 생긴다.
**진술이 게이트를 이겨야 하는가** — 진술은 *결과의 관측*이고 게이트는 *질의 문자열의
휴리스틱*이라 진술이 이기는 쪽이 맞아 보인다. 다만 게이트의 보호("경로 의존 질의에
틀린 답")를 잃는다. **분류는 계속 기록해서 상관을 측정한 뒤 정할 것.**

### 신뢰 — 새 공격면은 없다

`userKey` 는 이미 자기주장이다(D22). `answer` 도 같은 수준이고, **지금도** 클라이언트가
`search` → `read` → `end` 를 아무 pageId 로 불러 포스팅을 오염시킬 수 있다. 진술을
받는다고 새로 열리는 것은 없다.

### 모델이 안 부를 수 있다

도구 호출 한 번이 더 든다. 폴백이 있으니 퇴행은 없지만, **안 부르면 이 설계 전체가
무효**다. 그 비율이 곧 이 설계의 성립 조건이라 `/api/stats` 에 세야 한다.

## 먼저 잴 것 — 만들기 전에

### ① `dest = reads.last()` 의 오류율 (지금 잴 수 있다)

`agent.py` 가 도구 인자를 기록하게 됐으므로, 벤치 한 바퀴면 나온다:

```
읽은 pageId 순서 (args)  vs  모델이 낸 답 (ANSWER=<id>)
→ reads.last() != answer 인 비율
```

**이 값이 작으면 경로 1 은 만들 이유가 없다.** 추정이 이미 맞고 있다는 뜻이다.

### ② 학습된 앵커의 전이 이득 ($0)

`rank.py` 의 로컬판 절차에 0단계를 끼워 `q0 → LEARNED → q1·q2` 를 잰다.
지금 로컬판이 11/30 인데 얼마나 오르는지가 나온다. 세션을 안 쓴다.

**서버판도 같은 방법으로 잴 수 있다** — `LEARNED_ANCHOR` 필드를 임시로 채워 색인하고
`rank.py` 의 서버 열을 다시 잰다(지금 19/30).

### ③ 어휘가 못 찾는 문서에서의 행동 변화

오늘 실험이 못 본 축이다. 랭킹 밖 문서라면 힌트 유무가 *정답이냐 아니냐*를 가른다.
`docs/experiment-2026-08-14-learning.md` 의 "다음에 잴 것" 과 같다.

## 되돌아오는 조건

- ①의 오류율이 **10% 미만**이면 경로 1 을 접는다 — 고칠 것이 없다.
- ②에서 전이 이득이 **없으면** 경로 2 도 접는다 — 앵커를 늘려도 안 찾는다는 뜻이다.
- 둘 다 크면 **경로 2 부터** 만든다. 재색인 경계라 되돌리기가 싸고, 측정된 공백
  (97% 앵커 0)에 직접 닿는다.
