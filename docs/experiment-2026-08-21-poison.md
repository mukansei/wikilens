# 틀린 답을 학습시키면 얼마나 오래 아픈가 (2026-08-21)

**형상** 코퍼스 13,491건 · 서버 이미지 `bb4e04f80e82` · `:8790` 전용 서버 · **$0**
(모델을 안 쓰고 HTTP 세 번으로 궤적을 쌓는다). 하네스는 [`bench/poison.py`](../bench/poison.py).

## 왜 쟀나

`DECISIONS.md` D26 이 **오염이 일어난다**까지 말했다 — 학습 없는 대조군이 `answer` 를
부른 세 번이 세 번 다 틀린 문서였다. 거기에 "되돌리는 장치는 있다" 고 적었는데
**그 장치의 효과는 한 번도 안 쟀다.** 일화 하나(`rel=0.57 → 0`)뿐이었다.
가드가 있다는 사실과 가드가 작동한다는 사실은 다르다.

**실행 전에 예측을 못박았다**(`scratchpad/poison-design.md`). `eb_lower` 로 계산해
"1회 오염 → 미스 2회면 문턱 아래" 를 적어두고 쟀다.

## 재료 — 실제로 일어난 오염을 재현한다

합성이 아니다. G05 대조군 6세션 중 **5세션이 정답 대신 이 문서를 골랐고**, 그중
둘은 `answer` 로 못박기까지 했다.

```
  질의   ds앱 보안 관련해서 뭐 조치한다는 보고 있었는데
  정답   286067130   어휘 10위   ← limit 8 밖이다. 이게 뒤에서 문제가 된다
  오답   286066505   어휘  1위
```

## 절차

```
  ① 오염    검색 → **오답**을 읽음 → 종료      오답이 서빙될 때까지
  ② 회복    검색 → **정답**을 읽음 → 종료      오답 서빙이 멈출 때까지
  ③ 정상화  검색 → **정답**을 읽음 → 종료      정답이 서빙될 때까지
```

②가 실사용의 회복 모양이다 — 추천받은 문서를 열어보고 아니어서 다른 것을 읽는다.
그러면 `rejected = served - reads` 로 오답이 미스를 먹고 정답이 히트를 먹는다.

**②와 ③을 나눈 것이 이 측정의 요점이다.** 오답이 안 나오는 것과 정답이 나오는 것은
다르고, 그 사이에 **학습층이 아무 일도 안 하는 구간**이 있다.

## 결과 — 한 번 잘못 배우면 다섯 번 고쳐야 한다

```
  r0  오염    힌트 0                     오답 1위 · 정답 밖
  r1  오염    오답 서빙 ★                오답 1위 · 정답 밖     ← 1관측이면 발동
  r2  회복    오답 서빙                                        ← 피해
  r3  회복    오답 서빙                                        ← 피해
  r4  회복    서빙 없음                                        ← 오답이 밀려남(거부 2회)
  r5  정상화  서빙 없음                                        ← 무력 구간
  r6  정상화  정답 서빙 ★                오답 2위 · 정답 1위    ← 원상복구
```

```
    발동     오염 1회 관측
    회복     정답 읽기 2회 → 오답 서빙 멈춤
    정상화   정답 읽기 5회 → 정답 서빙
    피해     오답을 서빙받은 세션 3개
    무력     오답도 정답도 안 나온 세션 2개

    오염 1세션 : 정상화 5세션 = 5배
```

**예측이 맞았다** — "1회 오염 → 미스 2회" 그대로다. 세 번 돌려 세 번 같았다.

서버 자기진단도 따라왔다: `served 4 · rejected 2 · pWrong 0.5`. 이 지표는 만들어만
두고 실사용 값을 본 적이 없었는데, **오염이 실제로 그 자리에 나타난다.**

## 깊은 데서 배운 오답은 덜 생기고 더 오래 남는다

`hitWeight` 가 순위로 가중한다(1위 ×1 · 2~3위 ×2 · 그 아래 ×3)고, 히트만 가중하므로
**×3 으로 배운 간선은 미스 3번이라야 상쇄된다** — 코드가 그렇게 선언한다. 같은 질의의
어휘 5위 문서(`196981024`)를 오염시켜 시험했다. 질의·정답·서버가 전부 같고 **오염된
문서의 순위만 다르다.**

```
                   어휘 1위(×1)    어휘 5위(×3)
    발동             1관측           2관측       사전확률이 낮아 한 번으로는 부족
    회복             2거부           3거부       ← 선언대로 더 오래 남는다
    정상화           5회             5회
    피해             3세션           4세션       ← 총 피해는 오히려 크다
    비               5배             2배
```

**방향은 코드의 선언대로다.** 다만 읽는 값이 하나 더 있다 — **비가 작다고 덜 아픈 게
아니다.** 깊은 오답은 만들기 어려운 만큼 지우기도 어려워, 비(2배)는 작은데 실제 피해
세션은 더 많다(4 > 3). 비만 보면 반대로 읽는다.

## 딸려 나온 것 — 가장 강한 증거에 가장 약한 가중이 붙는다

`rank = ranked.indexOf(dest)` 인데 `ranked` 는 **응답에 실린 것**이고 기본 `limit` 이
8이다(프록시·이 측정 둘 다). 그래서:

```
  어휘 10위 정답을 grep 으로 찾아 읽음  →  ranked 에 없음  →  rank = -1  →  가중 ×1
```

**"깊은 곳에서 건져 올림 = 강한 증거" 라는 설계가, 검색이 아예 못 찾은 경우에는
×1 로 떨어진다.** `hitWeight` 의 `rank < 0 -> 1` 은 "순위 정보 없음" 이라 의도된
분기이고 그 자체로 틀리지 않았다. 문제는 **이 코퍼스에서 그 분기가 자주 열린다**는
것이다 — 학습이 의미 있는 띠가 어휘 8~25위인데(D23) `limit` 이 8이라, **띠의 대부분이
응답 밖**이다. 정상화가 5회나 걸린 이유이기도 하다.

**고치지 않는다 — 아직 무엇이 옳은지 모른다.** `limit` 을 늘리면 가중이 살아나지만
응답이 커지고, 별도 조회로 순위를 알아내면 검색을 두 번 하게 된다. 재고 나서 정할 것.

## 받아들이는 사람이 섞이면 — 셋 중 둘이면 안 낫는다

위는 **모두가 오답을 알아본다**는 낙관적 전제였다. 실사용에는 추천받은 오답을 그냥
읽고 끝내는 세션이 있고, 그때는 `rejected` 가 비어 미스가 아니라 **히트**가 된다.
`--accept N/D` 로 D세션마다 N세션이 수용하게 두고 쟀다(무작위가 아니라 결정적 교대 —
재현이 안 되면 회차를 비교할 수 없다).

```
    수용률     회복      정상화     피해 세션
      0%      2세션      5세션         3
     25%      4          7             6
     33%      6          9             8
     50%     18         22            21
     67%   안 됨(20+)   22            23
```

**선형이 아니다.** 수용률이 0 → 50% 로 갈 때 피해가 3 → 21 로 **일곱 배**가 된다.
그리고 **50%와 67% 사이에 절벽이 있다** — 셋 중 둘이 받아들이면 미스가 히트를 못
따라잡아 오답이 영영 안 내려간다.

67% 에서 정상화(22세션)가 회복보다 먼저 왔다는 것도 읽을 값이다. **오답이 안 내려간
채로 정답이 올라온다** — 둘 다 서빙되는 상태이고, 오염이 사라진 것이 아니다.

### 50% 부터는 줄다리기가 된다

원자료를 세어 보면 **둘 다 서빙된 세션이 따로 있다** — 50% 에서 네 번, 67% 에서 세 번,
전부 `오답 1위 · 정답 2위` 다. 정답이 2위까지 떠올랐다가 다시 가라앉기를 반복한다.

```
    50%  r10 r12 r16 r18     오답 1위 · 정답 2위
    67%  r14 r17 r23         오답 1위 · 정답 2위   ← r23 이 "정상화" 로 센 그 세션
```

거부하는 사람이 정답을 밀어올리는 만큼 받아들이는 사람이 오답을 떠받친다. **회복이
느린 것이 아니라 두 힘이 맞서고 있는 것**이고, 그래서 수용률이 조금만 더 오르면
회복 곡선이 아니라 평형으로 바뀐다 — 67% 가 그 평형이다.

### 예측이 빗나갔고, 이유가 하나였다

실행 전 예측은 0%→2 · 25%→3 · 33%→3 · 50%→8 · 67%→안 됨 이었다. 방향은 맞았지만
**중간 구간이 실측의 절반**이었다. 원인은 초기 상태를 잘못 둔 것 하나다 — 오염 국면이
오답을 **두 번** 읽는데(서빙 전 r0 · 서빙 시점 r1) 예측에서는 한 번으로 뒀다.

`h=2, m=0` 에서 출발하도록 고치자 **다섯 점이 전부 정확히 맞는다**(2 · 4 · 6 · 18 ·
안 됨). 모델이 틀린 게 아니라 초기값이 틀렸고, 그 차이가 배로 벌어졌다.

## 이 측정이 증명하지 못하는 것

- **한 질의 한 코퍼스다.** 사전확률이 어휘 점수라 코퍼스가 바뀌면 회차가 바뀐다.
- **수용이 규칙적이라고 봤다.** 결정적 교대라 재현되지만, 실사용의 수용은 몰린다 —
  같은 오답을 연달아 받아들이는 구간이 있으면 그 사이에 절벽을 넘을 수 있다.
- **실사용 수용률을 모른다.** 위 표는 "얼마면 어떻게 되나" 이지 "우리는 어디에
  있나" 가 아니다. `pWrong` 이 그 값에 가장 가까운 관측치다.
- **혼자 쓰는 경우다.** 여럿이 동시에 쓰면 피해 세션 수가 그만큼 곱해진다.
