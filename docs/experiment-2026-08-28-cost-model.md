# 비용 모델 실측 — D2 의 `1+n` 은 8배 과대평가였다 (2026-08-28)

설계와 예측은 [`design/design-2026-08-28-cost-model.md`](design/design-2026-08-28-cost-model.md)
에 **실행 전에** 적었다.

## 무엇을 쟀나

손익분기 `p_hit(n−1) > p_wrong`(D2)는 오답일 때 **`1 + n` 읽기**를 전제한다. `n` 은
기본 `limit=8` 이고 잰 적이 없었다. `pWrong` 이 게이트가 아니라는 것이 확인되면서
([1x-gate](design/design-2026-08-28-1x-gate.md)) 판정의 무게가 이 가정으로 옮겨왔다.

**오답을 먼저 읽은 세션이 그 뒤에 몇 개를 더 읽는가** — 그것이 `n` 이다.

## 결과

    유효 34세션 (ONAP 15,499건 · analyzer=english · C 서버판만)
    적중 30/34 · 격리 유출 0/34

    오답으로 시작한 세션 12건
      중앙값 1 · 평균 1.17 · 분포 {0:4, 1:5, 2:1, 3:1, 4:1}

**D2 의 가정은 8이고 실측 중앙값은 1이다.** 후보 8개를 다 읽은 세션은 하나도 없었고
최대가 4다. 세션당 `read` 총수도 중앙값 1 · 최대 5 였다.

표본을 늘려도 안 흔들렸다:

    15세션 → 오답시작  3건 · 중앙값 0.0 · 평균 0.33
    29세션 → 오답시작 10건 · 중앙값 1.0 · 평균 0.80
    34세션 → 오답시작 12건 · 중앙값 1.0 · 평균 1.17

## 예측이 하나 틀렸다

**"재질의가 읽기를 대체한다"** 고 적었다 — 오답을 받으면 후보를 더 읽는 대신 다시
검색할 것이고, 그러면 비용이 **턴**으로 나가 D2 모델에 없는 항이 된다고 봤다.

    예측  재질의가 절반 넘는 세션에서 발생
    실측  5/12 · 중앙값 0

**모델은 재질의도 많이 안 한다.** 오답을 하나 읽고 한 번 더 읽거나, 그냥 멈춘다.
비용이 다른 곳으로 옮겨간 것이 아니라 **애초에 작다.**

## 랭킹은 잘 돌고 있다

    정답 읽은 위치  {0:19, 1:6, 3:1, 4:1}   — 27건 중 19건이 첫 읽기
    정답 도달       27/34

오답으로 시작한 12건은 세 그룹에 몰렸다(N01 7 · N03 4 · N02 1). N04·N05 는 0이다 —
그룹 특성이 섞여 있으므로 이 12건이 코퍼스 전체를 대표하지는 않는다.

## 함의

오답 비용을 `1+k` 로 두면 D2 의 부등식은 이렇게 된다:

    p_hit·1 + p_wrong(1+k) + p_none·n < n     (k = 실측 1)

`k` 가 `n` 보다 훨씬 작으면 **오답이 거의 공짜**이고, 손익분기는 그만큼 느슨해진다.
서빙률이 소거된다는 앞선 결과(`pWrong < (n−1)/n = 0.875`)와 합치면 —
**`pWrong` 은 어떤 값이든 통과한다.** 게이트에서 완전히 뺀다.

**남는 관문은 발동 여부 하나다**(`served > 0`). 그것이 1.x 판정의 핵심이 된다.

## 이 측정의 한계

- **표본 12건.** 45세션 중 34건만 완주했고(11건은 계정 한도로 시작조차 못 함),
  그중 오답으로 시작한 것이 12건이다.
- **세 그룹에 몰렸다.** N04·N05 에서는 오답 시작이 0이라 그쪽 행동은 못 봤다.
- **ONAP 영어 코퍼스다.** 한국어에서 읽기 행동이 같다는 보장은 없다.
- **warm 이 섞였다.** 힌트를 받은 세션이 8건인데, 갈라 봐도 중앙값은 양쪽 다 1 이었다.
- **`gold` 가 하나라고 본다.** 답이 여러 문서에 걸치면 "오답 읽기" 로 잘못 센다.

## 여기까지 오는 데 두 번 헛돌았다

**첫 45세션은 통째로 버렸다**(약 $9). `--allowedTools` 가 개명 전 MCP 서버 이름
(`wiki`)을 가리켜 C 케이스가 `read` 를 거부당하고 **`Bash` 로 볼트를 직접 뒤졌다.**
세션은 정상 종료하고 `answer` 까지 냈으므로 결과 파일만 봐서는 몰랐다 — 도구 분포가
`search 2 · Bash 16` 인 것을 보고서야 알았다.

`agent.py` 주석은 이 실패를 예언하고 있었다("안 고치면 같은 실패가 되돌아온다").
도구 이름을 나열하지 않은 것은 맞았는데 **서버 이름을 박아** 같은 함정에 빠졌다.

**고친 것 셋:** 이름을 `.mcp.json` 에서 읽고, 격리 유출을 `leak` 필드로 결과에
기록하고(주석은 "도구 목록이 격리 검증" 이라고 오래 말했는데 **그 검사를 하는 코드가
없었다**), 계약으로 잠갔다.

그리고 준비하면서 결함 둘을 더 찾았다 — `setup.sh` 가 옛 컨테이너 경로를 써서 **벤치
서버가 빈 볼트를 볼 수 있었고**(그 상태도 `health` 200), `WIKILENS_VAULT` 를 안 봐서
**서버와 판정이 다른 볼트를 볼 수 있었다.** 셋 다 측정값을 조용히 거짓으로 만든다.
