# 1.x 를 낼 조건 — 실행 전 설계 (2026-08-28)

## 왜

"랭킹과 학습의 실효성이 충분히 검증되면 1.x 를 낸다" 는 방침이 섰다. **무엇이
"충분" 인지를 재기 전에 못박는다** — 값을 보고 기준을 정하면 유리한 쪽으로 읽는다.

이 문서는 **먼저 낸 기준 넷을 검토해 셋을 버린 기록**이기도 하다. 버린 이유가
다음에 재는 사람에게 더 쓸모 있다.

## 버린 기준 셋 — 왜 틀렸나

### `pWrong < 0.20` — 값이 4배 이상 틀렸고, 역할도 틀렸다

`pWrong`(코드)은 **서빙된 힌트 중** 거부율인데 D2 의 `p_wrong` 은 **전체 질의 중**
비율이다. 둘을 섞었다. 바르게 두면 서빙률 `s` 가 **소거된다**:

    p_hit = s(1−w)      p_wrong = s·w      (w = pWrong 코드값)
    s(1−w)(n−1) > s·w   →   (1−w)(n−1) > w   →   w < (n−1)/n

무작위 20만 회로 대조했다(`n ∈ {5,8,10,40}`, `s`·`w` 균등) — 예측과 실제 기대비용
비교가 **한 번도 안 어긋났다.**

    n=5 → 0.800    n=8 → 0.875    n=10 → 0.900    n=40 → 0.975

기본 `limit=8` 이므로 문턱은 **0.875** 다. D2 가 이미 말한 것과 같다 — "캐시가 확신
없을 때 침묵하면 `p_wrong → 0` 이라 거의 항상 이득이다."

**결론: `pWrong` 은 구속하지 않는다.** 게이트로 쓸 수 없다.

### `served ≥ 50` — 틀린 문턱에 맞춘 숫자였다

문턱이 0.875 면 상한을 그 아래로 누르는 데 표본이 거의 필요 없다(Wilson 95% 상한,
거부율을 올림해 보수적으로):

    거부율  0% → 1건      20% → 3건      50% → 4건
    거부율 70% → 17건     80% → 75건

50건은 내가 제안했던 `0.20` 기준의 숫자다(그 경우 16~25건). **표본 수는 관문이
아니다.**

### `answer` 라벨로 top-8 포함률 — 순환이다

`answer` 는 `read` 한 문서만 받고 `read` 는 `search` 결과에서 나온다(`grep`·`tree`
는 궤적을 안 남긴다). **찾았으니까 라벨이 있는 것**이라 포함률은 구조적으로 100%
근처다. 못 찾은 질의는 애초에 라벨이 없다 — survivorship bias.

**살릴 수 있는 형태는 순위 분포다.** 서버가 이미 `dest` 의 검색 순위를 기록한다
(1위 ×1, 2~3위 ×2, 그 아래 ×3 — 유용성 신호). 1위에서 찾은 것과 8위에서 건진 것은
다르고 그 차이는 순환이 아니다. **단 절대값이 아니라 변경 전후 비교로만 쓴다.**

## 남는 기준 넷

### ① 학습 층이 한 번이라도 말하는가 — `served > 0`

**넘었다(2026-09-04).** ONAP 벤치에서 반복 질의에 3회 서빙 · 거부 0
([experiment](../experiment-2026-09-04-learning-activation.md)).

**그런데 넘은 방식이 판정을 바꾼다.** 서빙에는 조건 둘이 동시에 서야 한다 —
**게이트 통과**(마커에 걸리거나 8낱말 이하)와 **표현 반복**이다. 한국어 실사용에서는
전자가 사실상 무료지만(`byKind` UNKNOWN 0%), **영어에서는 80% 를 자른다.**
`--wikilens.analyzer=english` 는 지원되는 설정인데 거기서 학습 층은 대부분 침묵한다.

즉 `served > 0` 은 **코퍼스 언어에 따라 답이 다른 관문**이었다. 아래는 재기 전의 서술이다.

지금 **`served = 0`** 이다(궤적 5 · terms 22). 힌트를 서빙한 적이 없으므로 `pWrong`
은 정의조차 안 된다. 이것이 첫 관문이고, 아래 ②가 그 전제다.

### ② 반복이 실제로 일어나는가 — 어휘가 약한 문서에서 10회

`serveThreshold = 0.45` 를 넘는 데 필요한 무패 관측을 `scoring_reference` 로 계산했다
(`prior_mean` 은 검색 점수/최고점 비):

    prior 0.05 → 10회     prior 0.2 → 8회     prior 0.5 → 4회     prior 0.8 → 1회

**학습이 가장 필요한 곳에서 가장 늦게 발동한다.** 어휘 검색이 못 찾는 문서일수록
prior 가 낮고, 그런 문서는 같은 표현으로 10번을 물어야 힌트가 나온다.

판정: **`prior < 0.2` 구간에서 발동한 항이 ≥ 1** 이어야 층이 제 일을 한 것이다.
이미 잘 나오는 문서(prior 0.8)에서만 발동하면 앵커가 하는 일을 반복하는 것이다.

### ③ 비용 모델이 맞는가 — **쟀다(2026-08-28). `1+n` 은 8배 과대평가였다**

실측: 오답으로 시작한 12세션에서 **추가 읽기 중앙값 1 · 최대 4**. 후보 8개를 다 읽는
세션은 없었다 — [experiment](../experiment-2026-08-28-cost-model.md).

**그래서 `pWrong` 을 게이트에서 완전히 뺀다.** 서빙률이 소거되어 문턱이 이미 0.875
였는데, 오답 비용까지 `1/8` 수준이면 어떤 값이든 통과한다. **남는 관문은 ①(발동
여부) 하나다.**

아래는 재기 전의 서술이다.

손익분기 전체가 이 가정 위에 있다:

    적중        1 읽기
    잘못된 힌트  1 + n 읽기      ← 이 n 이 검증된 적 없다
    힌트 없음    n 읽기

모델이 틀린 힌트를 받았을 때 **실제로 몇 개를 더 읽는지 잰 적이 없다.** `1+n` 이
아니라 `1+2` 라면 문턱이 `w < (n−1)/n` 이 아니게 되고, 위 계산이 전부 바뀐다.

잴 방법: 궤적에서 `rejected` 가 있는 세션의 **읽기 개수 분포**를 본다. 서버가 읽기를
이미 기록하므로 새 계측이 필요 없다.

### ④ 랭킹 품질 — 순위 분포의 변화

`dest` 순위 분포를 변경 전후로 비교한다. 절대 기준은 두지 않는다 — 위에 적은 순환
때문이다.

## 예측 (실행 전)

- **①은 팀 배포 전에는 안 넘는다.** 혼자 쓰면 같은 표현을 10번 반복할 일이 없다
  (지금 `multiQueryRate = 0.0`). 시간이 아니라 **사용자 수**의 문제다.
- **②가 넘으면 `pWrong` 은 통과한다.** 문턱이 0.875 라 거의 자동이다.
- **③이 가장 놀랄 자리다.** `1+n` 은 보수적으로 잡은 값이고, 모델은 오답을 받으면
  n 개를 다 읽지 않고 재질의할 가능성이 높다. 그러면 오답 비용이 과대평가돼
  **지금 문턱이 실제보다 엄격**하다.
  → **맞았다. 다만 이유가 달랐다** — 재질의로 옮겨간 것이 아니라(5/12·중앙값 0)
  **애초에 안 읽는다**(중앙값 1). 예측의 결론은 맞고 기제는 틀렸다.
- **④는 학습과 무관하게 잴 수 있다.** ①~③이 안 넘어도 이건 진행된다.

## 못 넘으면 무엇을 끄나

**층을 끄는 것이 실패가 아니다**(`README`). 못 넘었을 때의 행동을 미리 적는다.

| 안 넘은 것 | 하는 일 |
|---|---|
| ① `served = 0` 이 계속됨 | **학습 층을 끄고 1.x 를 낸다.** 코어와 앵커는 이미 측정됐다(D28) |
| ② prior 낮은 구간에서 발동 0 | 층은 켜두되 **"앵커의 복사본" 이라고 문서에 적는다** |
| ③ ~~비용 모델이 다름~~ | **쟀다(2026-08-28)** — 오답 비용이 `1+n` 이 아니라 `1+1` 이라 문턱이 더 느슨해졌다. `pWrong` 은 게이트에서 뺀다 |
| ④ 순위가 나빠짐 | 그 변경을 되돌린다 |

**1.x 는 학습 층 없이도 낼 수 있다.** 코어(미러 + 연산 넷)가 이 도구의 값어치이고,
랭킹 층 셋은 각자 증명 대상이라는 것이 이 저장소의 원래 입장이다.

## 이 문서가 틀릴 수 있는 자리

- `s` 가 소거된다는 유도는 **"서빙되면 적중 아니면 오답"** 을 전제한다. 힌트가 여럿
  서빙되고 그중 일부만 맞는 경우는 셋으로 안 나뉜다.
- Wilson 상한은 이항을 가정한다. 힌트가 세션 안에서 독립이 아니면 구간이 좁게 나온다.
- `prior_mean` 을 0.05~0.85 로 훑었지만 **실제 분포는 모른다.** 그 분포가 한쪽에
  몰려 있으면 ②의 "10회" 가 대표성이 없다.
