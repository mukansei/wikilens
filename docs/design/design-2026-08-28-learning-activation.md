# 탐색 궤적 학습 층은 값어치를 하는가 — 사전 등록 실험 계획 (2026-08-28)

> **이 문서는 측정 전에 작성됐다.** 결과를 보고 기준을 정하면 유리한 쪽으로 읽게 되므로,
> 가설·측정량·판정 기준을 실행 **전에** 고정한다. 결과는 별도 문서로 남기고 이 계획과
> 대조한다. 계획을 바꿔야 할 일이 생기면 **바꾼 사실과 이유를 결과 문서에 적는다.**

---

## 초록

WikiLens 는 Confluence 미러 위에 랭킹 층 셋(앵커 텍스트·계층·탐색 궤적 학습)을 얹는다.
이 중 **학습 층은 ONAP 코퍼스에서 한 번도 발동한 적이 없다**(`served = 0`). 본 실험은
그 0이 층의 성질인지 측정 설계의 산물인지 가르고, 발동한다면 **모델이 실제로 덜
헤매는지**를 잰다.

서빙 조건이 신뢰도와 커버리지의 **곱**이라는 점에서 가설이 갈린다 — 같은 표현의
반복은 커버리지 1.0 이지만, 표현이 바뀌면 0.43 이하로 떨어지고 반복 횟수로는 메울 수
없다(필요 커버리지의 하한이 0.59). 이 구조가 참인지, 그리고 발동이 모델의 행동을
바꾸는지를 두 단계로 잰다 — 발동 여부는 HTTP 만으로(무료), 효과는 실제 세션으로.

**결과에 따라 저장소 문서가 약속하는 바가 달라진다.** 그 갈림은 4.1 에 적었다.

---

## 1. 서론

### 1.1 배경

에이전트는 위키를 읽기 어렵다 — 인증이 필요하고, API 는 레이트리밋이 있으며, 무엇보다
grep 이 안 된다. WikiLens 는 위키를 마크다운 미러로 받아 네 연산(찾기·읽기·본문 스캔·
계층)으로 노출하고, 그 위에 랭킹 층 셋을 선택적으로 얹는다.

**층은 각자 값어치를 증명해야 한다**는 것이 이 저장소의 입장이다. 앵커 층은 측정됐고
(어휘 격차가 있을 때만 일한다), 계층은 랭킹에 아예 들어가지 않는다는 것이 확인됐다.
**학습 층만 미결이다.**

### 1.2 문제

ONAP 코퍼스(15,499건)에서 학습 층의 서빙 횟수는 **0**이다. 이 값은 둘로 읽힌다.

    (a) 층이 실제로 안 돈다        → 끄는 것이 맞다
    (b) 발동 조건을 안 만들고 쟀다  → 아직 아무것도 모른다

(b) 를 의심할 근거가 있다. 지금까지의 모든 에이전트 세션은 `--pattern spread`(기본값)로
돌았는데, 하네스가 그 순서를 **"섞여서 원인 분리가 안 된다"** 고 명시한다. 학습은 같은
질의의 반복에서 발동하도록 설계됐으므로, **반복 없는 순서로 재고 "발동하지 않는다" 고
말하는 것은 재려던 것을 재지 않은 것이다.**

### 1.3 연구 질문

    RQ1  ONAP 코퍼스에서 학습 층은 발동하는가
    RQ2  표현이 바뀌어도 발동하는가            (실사용 조건)
    RQ3  발동하면 모델이 덜 헤매는가            (값어치)

**RQ1 은 전제, RQ2 는 조건, RQ3 이 값어치 주장이다.** RQ1 이 거짓이면 나머지를 물을 수
없고, RQ2 가 거짓이면 RQ3 의 값어치에 단서가 붙는다.

### 1.4 범위

**ONAP 이 유일한 측정 대상이다.** 다른 코퍼스의 결과를 여기서 재현하는지 확인하는 것이
아니라, **여기서 처음부터 재는 것**이다. 따라서 결론도 ONAP 에 한정된다.

이 저장소에 학습 효과를 잰 선행 기록이 둘 있으나(턴 7.3→5.0 · 적중 1/6→6/6) 둘 다
다른 코퍼스이며, 본 실험의 비교 대상이 아니다.

## 2. 관련 연구

세 문헌이 이 설계의 서로 다른 결정을 지지한다. **관계 없는 것은 싣지 않는다.**

**① 어휘 격차가 실재한다는 전제** — Craswell, Hawking, Robertson, *Effective site
finding using link anchor information*, SIGIR '01
(https://dl.acm.org/doi/10.1145/383952.383999).

사람이 문서를 부르는 말과 그 문서의 제목이 다르다는 것, 그리고 앵커 텍스트가 그 격차를
메운다는 것이 이 문헌의 결과다. **본 실험의 H2 는 그 격차를 학습 층도 메우는지 묻는다**
— 앵커가 링크로 메우는 것을 궤적으로도 메울 수 있는가. H2 가 거짓이면 두 층은 같은
문제를 다르게 푸는 것이고, 참이면 학습 층은 다른 문제(반복 비용)를 푸는 것이다.

**② 사전확률이 변별을 못 하는 이유** — Robertson, Zaragoza, Taylor, *Simple BM25
extension to multiple weighted fields*, CIKM '04, pp.42–49.

3.2 에서 정답의 `score/top` 이 0.97~1.00 에 몰려 클램프 상한에 붙는 것을 관측했다.
이 문헌이 지적한 **여러 필드에 걸친 항의 과대평가**가 그 압축의 원인 후보다(본 시스템은
`TITLE`·`ANCHOR`·`BODY` 점수를 포화 뒤에 더한다 — 문헌의 비판 대상인 방식).
**즉 3.2 는 이 시스템의 랭킹 결합 방식이 만든 조건이며, 그것을 고치면 본 실험의 전제가
바뀐다.**

**③ 무클릭 종료를 실패로 세지 않는 근거** —
https://dl.acm.org/doi/10.1145/1571941.1571951 (good abandonment).

단계 2 에서 힌트를 받고도 아무 문서를 안 읽은 세션이 나올 수 있다. **그것을 "학습이
도움이 안 됐다" 로 세면 H3 을 과소평가한다** — 결과 제목만 보고 답했을 수 있기 때문이다.
본 시스템은 이를 `abandonedWithHints` 로 따로 세며, 본 실험도 그 구분을 따른다.

**본 실험의 위치.** 위 문헌은 전부 **랭킹 신호**에 관한 것이다. 탐색 궤적을 사용자
간에 공유해 랭킹을 보정하는 층의 **발동 조건**을 EB 하한과 커버리지의 곱으로 분해해
실측한 기록은 찾지 못했다.

## 3. 시스템과 이론

### 3.1 서빙 조건

서버가 학습 힌트를 내보내는 조건은 하나다(`TrajectoryStore.hints` · `Reliability`):

    rel = eb_lower(hits, misses, prior) × c  ≥  θ = 0.45

| 항 | 정의 | 출처 |
|---|---|---|
| `eb_lower` | Beta 사전분포의 경험적 베이즈 하한 | 관측 수와 사전확률 |
| `prior` | 그 문서의 Lucene 점수 / 최고점, `[0.05, 0.85]` 로 클램프 | 어휘 랭킹 |
| `c` | 이 문서를 가리킨 항 수 / 질의 항 수 | 질의 간 어휘 겹침 |

**두 항이 곱해진다.** 어느 한쪽이 작으면 다른 쪽으로 못 메운다 — 이것이 본 실험의
분석 축이다.

### 3.2 ONAP 에서 사전확률은 구속하지 않는다 (실측)

각 그룹의 정답이 첫 질의에서 받는 `score/top`:

    N02 0.968 (3위)   N03 1.000 (1위)   N04 0.984 (2위)   N05 1.000 (1위)
    N01 정답이 top8 밖 — 측정 불가

넷 다 클램프 상한 0.85 에 붙는다. 따라서

    eb_lower(1, 0, 0.85) = 0.616  ≥  θ = 0.45

**1회 관측으로 신뢰도 문턱을 넘는다.** BM25 점수가 좁은 폭에 압축돼 `score/top`
정규화가 변별을 못 하기 때문이며, 결과적으로 **`c` 가 유일한 변수**가 된다.

### 3.3 반복은 커버리지 부족을 보상하지 못한다

`rel ≥ θ` 를 `c` 에 대해 풀면:

| 관측 수 | `eb_lower` | 필요 `c` |
|---|---|---|
| 1 | 0.616 | ≥ 0.731 |
| 2 | 0.666 | ≥ 0.675 |
| 3 | 0.705 | ≥ 0.638 |
| 5 | 0.761 | ≥ 0.591 |

EB 하한이 로그적으로 증가하므로 **필요 커버리지가 0.59 아래로 내려가지 않는다.**

한편 질의 그룹 안 표현 간 어휘 겹침(공백 분리 기준 — 서버는 분석기 항으로 재므로 이
값은 **하한**):

    N01 c ≈ 0.13      N02 c ≈ 0.00~0.22    N03 c ≈ 0.14~0.43
    N04 c ≈ 0.14~0.17  N05 c ≈ 0.00~0.20

**전부 0.59 미만이다.**

### 3.4 H3 의 상한 — 학습이 닿을 수 있는 자리

학습은 **순위를 바꾸지 없던 문서를 만들지 않는다.** 따라서 효과의 상한은 현재 랭킹이
남긴 여지로 정해진다. ONAP 15질의에서 C 서버판의 정답 순위는 이렇다:

    [1, 1, 1, 2, 2, 3, 3, 8]  top8 안 8건    — 순위가 바뀌어도 가시성은 그대로
    [12, 15, 18]              9위 이하 3건   — 끌어올리면 새로 보인다
    밖 4건                                   — 후보에 없으면 학습만으로는 못 만든다

**개선 여지는 15건 중 최대 7건**이고(9위 이하 3 + 밖 4), 나머지 8건은 이미 모델이 보는
범위(`limit=8`)에 있어 순위가 올라도 **도달성이 안 바뀐다.**

개선 여지가 있는 7건은 이렇게 흩어져 있다:

    N01 q0·q1 밖 · N02 q1 18위 · q2 밖 · N03 q1 12위 · q2 15위 · N05 q2 밖

**세 표현은 대등하다.** q0 가 "원본" 이고 q1·q2 가 "변형" 인 것이 아니라, 같은 답을
뜻하는 세 가지 자연어 표현이다. `repeat` 조건은 그 셋을 **각각** 반복하므로
(`plan()` 이 `qi` 를 순회한다), **개선이 필요한 질의도 발동 대상이다.**

**그러므로 H3 의 상한은 이렇게 갈린다:**

| 대상 | 건수 | 학습이 무엇을 하나 |
|---|---|---|
| 이미 top8 안 | 8 | 순위만 바뀐다 — **도달성은 그대로** |
| 9위 이하 | 3 | 끌어올리면 새로 보인다 |
| 후보 밖 | 4 | **새 후보로 넣을 수 있다** — 아래 참고 |

**"후보 밖" 도 학습이 닿는다.** `SearchService.fuse` 가 어휘 결과에 없는 페이지를
`source = "learned"` 로 **추가**하기 때문이다:

```kotlin
val cur = acc[h.pageId]
if (cur != null) { cur.score += boost; cur.source = "both" }
else             { acc[h.pageId] = Acc(boost, "learned", h.reliability) }   // ← 새 후보
```

이 분기는 한때 죽어 있었고(어휘 결과에 없는 후보를 걸러 버렸다) 그것이 "학습 레이어의
존재 이유가 죽어 있었다" 로 기록돼 있다. 지금은 산다.

**따라서 H3 의 이론적 상한은 15건 중 7건**(9위 이하 3 + 밖 4)이고, 나머지 8건은
개선해도 모델이 보는 범위가 안 바뀐다.

**단 "밖 4건" 이 실현되려면 그 질의로 정답을 읽은 궤적이 먼저 있어야 한다.** 실험에서는
정답을 읽혀 학습시키므로(5절) 성립하지만, **실사용에서는 못 찾은 문서를 읽을 수 없다** —
누군가 다른 경로(`grep`·`tree`)로 찾아 읽어야 그 궤적이 생긴다. 이 실험이 재는 것은
그래서 **상한**이다.

## 4. 가설

**H1.** 같은 질의를 반복하면 학습 층이 발동한다.
근거: `c = 1.0` 이므로 `rel = 0.616 ≥ θ`. **2회차부터 서빙된다.**

**H2.** 같은 답을 뜻하는 다른 표현으로는 발동하지 않는다.
근거: `c ≤ 0.43` 이므로 `rel ≤ 0.27 < θ`. 3.3 에 의해 반복으로도 못 넘는다.

**H3.** 발동하면 모델이 덜 헤맨다.
힌트를 받은 세션은 안 받은 세션보다 턴·도구 호출·읽기가 적다.

### 4.1 H2 가 참일 때의 함의

저장소 문서는 이 도구를 **"제목에 없는 표현으로도 찾는다"** 로 정의하고, 그 격차를
메우는 층으로 셋을 든다. **H2 가 참이면 학습 층은 그 역할을 하지 못한다** — 표현이
같아야 발동하므로, 격차를 메우는 것이 아니라 **이미 맞힌 것을 굳히는** 층이다.

그러면 층의 서술이 "새 문서를 찾아준다" 에서 **"같은 질문의 반복 비용을 줄인다"** 로
바뀌어야 한다. 1.x 가 무엇을 약속하느냐가 여기서 갈린다. **이것이 본 실험의 실무적
기여다.**

## 5. 방법

### 5.1 고정하는 것

    코퍼스  ONAP 15,499건 · analyzer=english
    서버    :8790 (운영 :8787 과 격리)
    케이스  C 서버판만 — A(원시 grep)·B(로컬판)에는 학습 층이 없다
    질의    N01~N05 · 그룹당 3표현 · gold 는 ONAP 실제 페이지
    모델    세션 기록의 `model` 필드로 확인 — 바뀌면 비교가 무효다

### 5.2 두 단계

**나누는 이유:** 서빙이 0인 채로 유료 세션을 태우면 "학습이 행동을 안 바꿨다" 와
"애초에 학습이 없었다" 가 구별되지 않는다. **단계 1 이 관문이고 도구도 다르다.**

|  | 단계 1 | 단계 2 |
|---|---|---|
| **묻는 것** | 발동하는가 (H1·H2) | 행동을 바꾸는가 (H3) |
| **도구** | `bench/learn.py` — HTTP 세 번 | `bench/agent.py` — 실제 세션 |
| **비용** | $0 · 수 분 | $18~29 · 45세션 |
| **독립변수** | 질의 순서 (R vs T) | 회차 (rep0 vs rep1·2) |
| **판정** | 서빙 시작 회차 | 턴·호출·읽기 |

**단계 1 의 독립변수 — 질의 순서**

| 조건 | 순서 | 이론적 `c` | 가설 |
|---|---|---|---|
| **R** `repeat` | 같은 질의 연속 3회 | 1.0 | H1 |
| **T** `transfer` | q0 를 2회 학습 → q1·q2 각 1회 | 0.00~0.43 | H2 |

R 과 T 사이에 **서버 상태를 초기화한다** — R 의 궤적이 T 로 흘러가면 T 의 결과가 R 의
잔여물이 된다.

**단계 2 의 독립변수 — 회차 안에서 갈린다**

`repeat` 은 같은 질의를 연속으로 돌므로 **rep0 이 궤적을 쌓고 rep1·rep2 가 그것을
받는다.** 따라서 "cold 45세션 vs warm 45세션" 이라는 이전 구상은 성립하지 않는다 —
cold 로 시작해도 두 번째 회차부터는 warm 이다.

**대신 회차가 곧 조건이다:**

| 회차 | 서버가 들고 있는 것 | 기대 |
|---|---|---|
| rep0 | 그 질의에 대한 궤적 0 | 힌트 없음 — **대조군** |
| rep1·rep2 | rep0 이 남긴 궤적 | 힌트 있음 — **처치군** |

**세션 안에서 짝지어 비교한다**(paired). 같은 질의·같은 모델·같은 서버이므로 회차
말고는 다른 것이 없다 — 별도의 cold 실행이 필요 없고 45세션이면 된다.

**주의:** 회차는 학습 말고도 **캐시·순서 효과**를 함께 담는다. 모델이 같은 질문을 두
번째 볼 때 더 빠른 것이 학습 때문인지 다른 이유인지 이 설계로는 못 가른다.
그래서 **`hints` 로 한 번 더 가른다** — rep1 인데 힌트를 못 받은 세션이 있으면 그것이
순서 효과만의 대조군이 된다(5.3).

**순서는 `repeat` 으로 고정한다.** H2 가 참이면 `transfer` 에서는 힌트가 안 나와
대조가 성립하지 않는다 — H2 가 거짓이면 그때 설계를 다시 본다(7절).

**단계 1 이 무료이고 결정적이므로, 예측이 깨지면 단계 2 를 돌지 않는다.**

### 5.3 측정량

| 값 | 출처 | 무엇을 말하나 |
|---|---|---|
| 서빙 시작 회차 | `learn.py` | H1·H2 의 주 결과 |
| `rel` | 검색 응답 | 이론값 0.616 과 대조 (3.2 검증) |
| `hints` | 세션 응답 | 그 세션이 실제로 힌트를 받았나 |
| `turns`·`calls`·읽기 수 | 세션 기록 | H3 의 주 결과 |
| `hit`·`rank` | 판정 | 발동이 답을 바꿨나 (부수) |

**`hints` 로 가른다 — 회차만으로는 부족하다.** rep1 이라고 다 힌트를 받는 것이 아니다
(그 질의의 `rel` 이 문턱을 못 넘을 수 있다). 세 갈래로 나눈다:

    rep0                    힌트 없음        기준
    rep1·2 · hints = 0      힌트 없음        ← 순서·캐시 효과만
    rep1·2 · hints > 0      힌트 있음        ← 학습 효과 + 순서 효과

**둘째와 셋째의 차이가 학습의 몫이다.** 첫째와 셋째만 비교하면 순서 효과를 학습으로
읽는다 — 이 저장소가 겪은 오독과 같은 모양이다(구별 없이 묶으면 학습이 안 닿은 그룹의
잡음이 중앙값을 지배한다).

## 6. 예측 (실행 전 고정)

1. **H1 참** — `repeat` 2회차부터 서빙. 관측 `rel` 이 0.616 ± 0.05.
2. **H2 참** — `transfer` 는 끝까지 0. **예외 후보는 N05**(q0·q1 이 5항이라 겹침 하나가
   `c` 를 크게 올린다). 분석기가 불용어를 빼면 넘을 수 있다.
3. **H3 은 절반에서만 참** — 3.4 대로 상한이 15건 중 7건이다. 나머지 8건은 이미
   top8 안이라 순위가 올라도 모델의 행동이 안 바뀐다. 따라서 **전체 평균으로 보면 효과가
   묽어진다** — `hints > 0` 인 세션만 갈라 봐야 보인다(5.3).
4. **그룹마다 갈린다** — prior 가 낮은 그룹에서 발동이 늦거나 없고, **그 그룹이 학습이
   가장 필요한 곳**이다. N01 은 정답이 top8 밖이라 가장 유력한 후보다.

## 7. 사전 등록한 판정

| 관측 | 해석 | 조치 |
|---|---|---|
| H1 거짓 | 층이 실제로 안 돈다 | **끄고 1.x.** 코어·앵커는 이미 측정됨 |
| H1·H2·H3 참 | 값어치 있으나 조건부 | 켠 채 1.x. **"정확 반복에서만"** 을 문서에 명시(4.1) |
| H1·H2 참 · H3 거짓 | 발동하는데 도움이 안 됨 | **개선 여지가 있던 7건**(3.4)에서도 안 바뀌었는지 먼저 확인한다. 거기서도 0이면 끈다 |
| H2 거짓 | 표현 전이가 된다 | 그 그룹의 항수·겹침을 따로 본다. 단계 2 설계를 다시 본다 |

**H3 의 판정 기준:** 5.3 의 셋째 갈래(`rep1·2 · hints>0`)가 둘째 갈래
(`rep1·2 · hints=0`)보다 **턴 중앙값이 작고**, 그 차이가
세션 간 변동에 묻히지 않을 것. 하네스 주석이 변동을 최대 7배로 기록하므로, 표본이 적을
때 유의성 검정은 하지 않는다 — **분포를 겹쳐 보고 겹치면 "차이 없음" 으로 읽는다.**

**완주 세션 수를 함께 보고한다.** 계정 한도로 조기 종료되면 "서빙 0" 이 표본 부족일 수
있다 — **완주 15세션 미만에서 서빙 0이면 판정을 보류한다.**

## 8. 타당성 위협

### 8.1 내적 타당성 — 위협과 완화

**셋 다 이미 겪은 것이다.** 그래서 "조심한다" 가 아니라 장치와 절차를 적는다.

| 위협 | 무엇이 일어나나 | 완화 |
|---|---|---|
| **격리 유출** | C 케이스가 MCP 밖 도구로 볼트를 직접 뒤진다. **세션은 정상 종료하고 `answer` 까지 낸다** | 세션마다 `leak` 필드를 기록하고 **첫 세션에서 확인한 뒤 나머지를 돌린다.** 2026-08-28 추가 — 그전에는 45세션(약 $9)을 유출 상태로 태운 뒤에 알았다 |
| **서버 상태 오염** | 실행 중 `setup.sh` 를 부르면 `srv-state` 가 지워져 `mode` 가 갈린다. 두 묶음을 합칠 수 없다 | **실행 중에는 `setup.sh` 를 부르지 않는다.** 서버가 죽으면 `docker start` 로 컨테이너만 되살린다. 결과 파일의 `mode` 를 분석 전에 집계한다 |
| **조기 종료** | 계정 한도가 예산 상한보다 먼저 걸린다(지난 세 번 모두). 0토큰 세션이 "실패" 로 기록된다 | 분석 시 `error` 와 `tokens>0` 으로 거른다. **완주 15세션 미만이면 판정을 보류한다**(7절). 이어받기가 실패 건만 다시 돈다 |

**세 위협 모두 "결과 파일이 정상으로 보인다" 는 공통점이 있다.** 그래서 완화가 전부
**분석 전 확인 절차**다 — 측정 뒤에 보면 이미 늦다.

### 8.2 구성 타당성

- **`c` 를 공백 분리로 근사했다.** 서버는 분석기가 만든 항으로 잰다(소문자화·어간·
  불용어 제거). 불용어가 빠지면 분모가 줄어 `c` 가 올라가므로 **3.3 의 값은 하한이다.**
- **"덜 헤맨다" 를 턴으로 잰다.** 턴은 대리 변수이고, 한 턴에 여러 도구를 부르면 실제
  작업량과 어긋난다. `calls` 를 함께 본다.
- **정답을 읽혀 학습시킨다.** 학습에 가장 유리한 조건이므로 **효과의 상한**을 재는
  것이다. 실사용은 엉뚱한 문서도 읽으므로 이보다 나쁘다.

### 8.3 외적 타당성

- **코퍼스가 ONAP 하나다.** 이것이 의도이나(1.4), 결론도 ONAP 에 한정된다.
- **질의 15개 · 그룹 5개.** 사람이 만든 "같은 답의 다른 표현" 이라 실사용 분포와 같다는
  보장이 없다. **RQ2 의 답은 이 질의 집합이 대표하는 만큼만 유효하다.**
- **N01 은 정답이 top8 밖**이라 3.2 의 근거에서 빠져 있다.
