# 관리 토큰을 첫 기동에 생성한다 — 실행 전 설계 (2026-08-26)

## 무엇을 푸는가

`docker run` 이 두 줄인데 하나가 `-e WIKILENS_ADMIN_TOKEN=…` 이다. 이걸 없애면
한 줄이 되지만, **없애면 기본이 열림이 된다** — `CLAUDE.md` 가 명시한 자리다:

> 관리 API 기본이 **잠김** — 열림이 기본이면 **조용히 열린 채 배포된다**

그래서 "사람이 안 정한다" 와 "토큰이 없다" 를 갈라야 한다.

## 설계 — 진입점이 채워 넣는다

```
① WIKILENS_ADMIN_TOKEN 이 이미 있으면 그것을 쓴다      명시가 항상 이긴다
② state/admin-token 파일이 있으면 그것을 쓴다          재기동에 같은 값
③ 둘 다 없으면 만들어 저장하고 로그에 한 번 찍는다
```

**`AdminGuard` 는 안 건드린다.** 서버 코드는 여전히 `wikilens.admin-token` 하나만
보고, 비면 404 다. 진입점이 그 값을 채워 줄 뿐이라 **잠김이 기본이라는 성질이
그대로다** — 값이 없으면 여전히 잠긴다.

## 판정 기준 (실행 전에 고정)

- **재기동에 같은 토큰** — `state` 를 마운트했으면 파일이 남아 그대로다.
- **명시가 이긴다** — `-e` 를 주면 파일을 무시한다.
- **파일 권한 600** — `state` 는 호스트에 바인드되므로 사람이 읽을 수 있어야 하지만
  다른 사용자에게는 아니다.
- **`state` 를 안 붙이면 매번 새 토큰** — 그게 맞는 동작이다. 그 경우 재색인도
  세션도 컨테이너와 함께 사라지므로 토큰만 유지될 이유가 없다. **로그가 그 사실을
  말해야 한다.**

## 예측

- 첫 기동: 토큰 생성 로그 한 줄. `/api/admin/*` 이 그 토큰으로 열린다.
- 재기동: 생성 로그 없음. 같은 토큰이 계속 통한다.
- `-e` 로 주면: 파일이 있어도 그 값이 이긴다.

## 안 하는 것

- **`AdminGuard` 에 파일 읽기를 넣기.** 서버 코드가 배포 형태(컨테이너)를 알게 된다.
  진입점은 컨테이너 것이고 서버는 어디서든 도는 물건이다.
- **토큰을 로그에 매번 찍기.** 생성할 때 한 번이다 — 로그는 공유되는 자리다.
