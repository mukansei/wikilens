## 무엇을 물었나

`DECISIONS.md` D23 이 계산으로 낸 것 — "학습 층이 가장 필요한 곳에서 가장 늦게

## 설계

질의 하나(`「ga 보려면 어디로 들어가야 해?」`, G09)를 **4회 반복**하고 회차마다 세
방식을 각각 독립 세션으로 돌렸다. 궤적은 비우고 시작했다.

| | 역할 | 학습 |
|---|---|---|
| A 원시 grep | 대조군 | 없음 |
| B 로컬판 | 대조군 | 없음 |
| C 서버판 | 처치군 | **있음** |

**왜 G09 인가.** 정답이 어휘 랭킹 19위라 힌트가 붙으면 1위가 된다 — 변화가 보일 자리로
골랐다. G04(1위)는 발동해도 답이 안 바뀌고, G01(랭킹 밖)은 셋 다 못 찾아 변별이 없다.

**왜 4회인가.** `learn.py` 사전 측정에서 G09 는 **3관측**이 쌓여야 문턱을 넘었다.
reps 3 이면 그 전환을 못 본다.

## ① 힌트는 예측보다 두 회차 빨리 붙었다

`learn.py` 는 **r3** 을 예측했는데 실제로는 **r1** 에 나왔다. `learn.py` 는 세션당
궤적 1건을 만들지만 **에이전트는 한 세션에서 검색을 여러 번** 해서 관측이 빨리 쌓인다.

**실사용에서 학습이 계산보다 빨리 발동한다.** D23 의 "몇 관측이 필요한가" 는 하한으로
읽어야 한다 — 실제 세션은 그보다 적은 회차에 도달한다.

## ② r2 에서 힌트가 사라진 것은 미스 벌점이다

궤적이 `1 → 3` 건으로 늘었는데 힌트는 `1 → 0` 이 됐다. **버그가 아니라 설계된
자기교정이다** — `TrajectoryStore.apply` 가 서빙했는데 안 읽힌 힌트를 미스로 되돌린다.

```
rejected   = served - reads          서빙했는데 안 읽음
passedOver = reads.dropLast(1) - dest 열어보고 지나침
→ 둘 다 slot[1]++ (미스)
```

`ebLower(hits, misses, prior=0.85)` 로 계산하면 관측과 맞는다:

| 회차 | 맞음 | 벌점 | ebLower | 문턱 0.45 |
|---|---:|---:|---:|---|
| r1 | 1 | 0 | **0.616** | 서빙 |
| r2 | 2 | 2 | **0.431** | 안 됨 |
| r3 | 3 | 1 | **0.565** | 서빙 |

`0.431` 이 문턱 바로 아래다.

**확정은 아니다.** `agent.py` 가 *어느 문서를 읽었는지*와 *질의를 어떻게 고쳐 쳤는지*를
기록하지 않아, 모델이 r2 에 말을 조금 바꿔 물었을 가능성을 배제할 수 없다(그러면 항이
달라져 커버리지가 떨어진다). 둘을 가르려면 기록을 늘려 다시 재야 한다.

**따라오는 아이러니:** 이 실험에서는 **벌점이 정당했다.** 어휘가 19위로 주고 에이전트가
찾아내니 힌트를 안 쓴 것이 맞는 행동이다. 그런데 그것이 학습을 깎았다 —
**힌트가 필요 없는 문서에서는 학습이 자기를 지운다.**

## ③ 행동은 안 바뀌었다 — 대조군이 그 판정의 근거다

C 의 도구 호출이 `6·6·6·5` 로 거의 그대로다. 회차 안의 토큰 변동을 학습으로 읽을 수
있는지는 **학습이 없는 A·B 가 얼마나 흔들리는가**로 판정한다.

| | 최고·최저 간격 |
|---|---:|
| A 원시grep | 54% |
| B 로컬판 | **71%** |
| C 서버판 | **29%** |

**C 의 폭이 대조군보다 좁다.** 마지막 회차의 176K 는 그 잡음 범위 안이다.

## ④ 힌트가 없어도 12/12 정답

r0 도 맞혔다. 어휘 19위를 에이전트가 파고 내려가 찾아냈다는 뜻이고,
**학습이 개입할 여지 자체가 없었다** — 설계의 전제("19위면 놓칠 것")가 틀렸다.

## 판정

**학습 층은 작동한다. 이 실험에서 값어치는 증명되지 않았다.**

힌트는 실제로 서빙됐고, 서빙되면 정답이 19위 → 1위로 올라온다. 그런데 모델이 힌트를
쓰지 않은 것이 아니라 **쓸 필요가 없었다.**

`CLAUDE.md` 가 "랭킹 층 셋은 각자 값어치를 증명해야 한다" 고 적어둔 그 판정이다.
**이 코퍼스·이 질의에서는 증명 실패다.**

## 이 결과가 말하지 못하는 것

- **표본 4.** 처치군이 회차당 1세션이라 통계 검정을 붙일 수 없다. 위 폭 비교는 방향만 읽는 근거다.
- **질의 하나.** 한 문서·한 표현이다.
- **정답이 쉬웠다.** 어휘가 아예 못 찾는 문서에서 다시 재야 한다.
- **표현 전이 미포함.** 같은 표현을 반복했다. 다른 표현으로는 안 된다는 것을 따로 쟀다(D23 ②).
- **Bash 를 쓰면 Haiku 가 붙는다.** Claude Code 가 명령 실행 전 안전성을 검사한다.
  답은 전부 Opus 5 가 만들고 Haiku 는 토큰의 2%·비용의 1% 지만, **Bash 를 많이 쓰는
  A·B 에 더 붙는다**(실측: 질의만 하면 Opus 단독, Bash 를 쓰면 둘).

## 다음에 잴 것

**어휘가 못 찾는 문서로 바꿔 반복한다.** 이번 문서는 학습 없이도 도달해 처치의 효과가
나타날 자리가 없었다. 랭킹 밖 문서라면 힌트 유무가 *정답이냐 아니냐*를 가른다.

다만 그런 문서일수록 **발동이 늦다** — 사전확률이 낮아 관측이 더 필요하다(D23 ①).
회차를 늘려야 하고 그만큼 비싸진다. **그 비대칭 자체가 이 층의 알려진 약점이다.**

그리고 **`agent.py` 가 도구 인자를 남기게 해야 한다.** 이번에 두 번 막혔다 — ②의 원인
확정과, `tree` 에 준 depth 를 토큰 총량으로 역산한 것.
