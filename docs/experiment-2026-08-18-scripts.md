# 문자 집합 필터가 실제로 답을 바꾸는가 (2026-08-18)

**형상** `d3401d08`·`d084750e` · 코퍼스 13,947건 · **$7.12**
**구성** 같은 볼트를 두 번 빌드해 대조 — `wikilens build` 와
`wikilens build --scripts hangul,ascii` (문턱 0.10 · 본문만). 제외 473건(3.4%).
`bench/rank.py` 30질의($0)와 G09 에이전트 12세션 두 벌로 쟀다.

필터를 만들어 놓고 "적중률을 올렸는지" 는 재지 않은 채였다. 그것을 쟀고,
**두 측정 장치가 정반대로 답한다** — 어느 쪽을 믿을지가 이 기록의 요점이다.

## 요약

| | 필터 끔 | 필터 켬 |
|---|---|---|
| `rank.py` 상위 10 적중 (서버판 30질의) | 16 | **16** |
| G09 에이전트 적중 (warm 9세션) | 1/9 | **4/9** (p=0.294) |
| G09 에이전트 적중 (cold 3 포함 12세션) | 2/12 | **6/12** (p=0.193) |
| 베트남어 번역본을 답으로 고른 횟수 | 6 | **0** |

## 결과 — 랭킹은 거의 안 움직인다

```
       바뀐 질의   방향                   상위 10 적중
  A 원시grep  12   전부 개선 (4~151위)      0 →  0 / 30
  B 로컬판     5   개선 4 · 악화 1          6 →  7 / 30
  C 서버판     4   개선 4 · 악화 0         16 → 16 / 30
```

제외는 473건(3.4%)이다. **A 가 전부 조금씩 개선된 것이 이 표의 해석을 준다** —
원시 grep 에는 랭킹이 없고 후보만 줄었는데도 순위가 오른다. 즉 C 의 개선 4건도
"경쟁자 473건이 사라진 만큼" 이지 **필터가 랭킹 신호를 준 것이 아니다**(1~5칸).

**정답이 상위 10 안으로 새로 들어온 질의는 하나도 없다.** 이 30질의에서
`rank.py` 로 보이는 효과는 사실상 0 이다.

## 그런데 에이전트 벤치는 다르게 말한다

`rank.py` 는 **정답의 순위**만 본다. 모델이 무엇을 답으로 고르는지는 안 본다.
G09 9세션(`experiment-2026-08-14-answer.md`)의 최종답을 문자 비중과 대조하면:

```
  111715171   6회   비중 0.171   ← 필터가 뺀다 (베트남어 번역본)
  363013408   3회   비중 0.000
  285314444   2회   비중 0.000   ← 정답
  175931444   1회   비중 0.000
```

**모델이 절반의 세션에서 답으로 고른 문서가, 필터가 빼는 바로 그 문서다.**
그 문서의 정답 순위는 20위 → 15위로 5칸 올랐을 뿐이라 `rank.py` 에는 안 보인다 —
번역본이 정답보다 위에 있었고 모델은 위에서부터 읽으므로, **후보 목록에서 사라지는
것과 순위가 5칸 오르는 것은 모델에게 전혀 다른 사건이다.**

## 그래서 필터 켠 볼트로 G09 를 다시 돌렸다 — 적중 1/9 → 4/9

**돌리기 전에 판정 기준을 못박았다.** 결과를 보고 정하면 유리한 쪽으로 읽게 된다.
그리고 그 계산이 먼저 알려준 것이 하나 있다 — **적중률로는 이 실험이 결판을 못 낸다.**
기준선 1/9 에 대해 Fisher 정확검정으로 p<0.05 에 닿으려면 **8/9 이상**이어야 한다.
n=9 의 한계이지 효과의 부재가 아니다. 그래서 1차 판정을 결정적 관측 둘로 잡았다:

- **① 번역본이 답에서 사라지는가** — 색인에서 뺐으니 반드시 0. 확인일 뿐이다.
- **② 그 자리를 정답이 가져가는가, 다른 오답이 가져가는가** — 이것이 진짜 질문이다.

```
  필터 끔 (12세션)              필터 켬 (12세션)
    111715171  6회  ← 번역본       285314444  6회  ★정답
    363013408  3회                363013408  2회
    285314444  2회  ★정답          175931444  1회
    175931444  1회                111346013  1회   ← 새로 나타난 한국어 오답
                                  43930099   1회   ← 같음
```

**번역본이 비운 6자리를 정답이 4, 새 오답이 2 가져갔다.** 질의 셋이 전부 같은
방향이다 — q0 `1/3→2/3` · q1 `0/3→1/3` · q2 `0/3→1/3`.

**예측이 빗나간 자리를 적어둔다.** 돌리기 전 판단은 "정답이 15~19위라 1위가 사라져도
모델은 새 1위를 읽지 정답까지 안 내려간다" 였고 틀렸다. 모델은 1위만 읽는 것이
아니라 여러 건을 읽고 고르는데, **번역본이 1위에 있으면 거기서 답을 확정하고 멈춘다.**
사라지면 계속 탐색해 19위의 정답에 닿는다. 갈린 것은 순위 5칸이 아니라 **탐색을
멈추느냐 계속하느냐**다. 순위 지표가 이 효과를 못 보는 이유도 같다.

## 결론

- **효과의 방향과 크기는 일관되지만 통계적으로 확정은 아니다**(p=0.19~0.29).
  질의 셋 모두 개선, 적중 3배. 확정하려면 그룹을 늘려야 한다.
- **판정 장치는 `rank.py` 가 아니라 에이전트 벤치다.** 순위는 안 움직이는데 답이
  바뀐다 — 같은 변화를 한쪽은 0으로, 다른 쪽은 3배로 읽는다.
- **기본값은 계속 꺼짐이다.** 증거가 그룹 하나이고, 켜면 473건이 grep 에서도
  사라진다. 다국어 코퍼스를 가진 사용자가 켜는 선택지로 남긴다.
- **다음에 잰다면** 번역본이 섞인 그룹을 더 찾아 G09 밖에서 재현되는지 본다.
  지금은 "번역본이 1위인 질의" 하나에서만 확인된 효과다.
