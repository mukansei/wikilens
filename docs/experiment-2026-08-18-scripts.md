# 문자 집합 필터가 실제로 답을 바꾸는가 — 30질의 랭킹 대조 (2026-08-18)

**형상** `d3401d08` · 코퍼스 13,947건 · **$0** (`bench/rank.py`, 모델 호출 없음)
**구성** 같은 볼트를 두 번 빌드해 대조 — `wikilens build` 와
`wikilens build --scripts hangul,ascii` (문턱 0.10 · 본문만). 정답 문서는 10건이고
**하나도 제외되지 않았다.**

필터를 만들어 놓고 "적중률을 올렸는지" 는 재지 않은 채였다. 그것을 쟀다.

## 결과 — 랭킹은 거의 안 움직인다

```
       바뀐 질의   방향                   상위 10 적중
  A 원시grep  12   전부 개선 (4~151위)      0 →  0 / 30
  B 로컬판     5   개선 4 · 악화 1          6 →  7 / 30
  C 서버판     4   개선 4 · 악화 0         16 → 16 / 30
```

제외는 473건(3.4%)이다. **A 가 전부 조금씩 개선된 것이 이 표의 해석을 준다** —
원시 grep 에는 랭킹이 없고 후보만 줄었는데도 순위가 오른다. 즉 C 의 개선 4건도
"경쟁자 473건이 사라진 만큼" 이지 **필터가 랭킹 신호를 준 것이 아니다**(1~5칸).

**정답이 상위 10 안으로 새로 들어온 질의는 하나도 없다.** 이 30질의에서
`rank.py` 로 보이는 효과는 사실상 0 이다.

## 그런데 에이전트 벤치는 다르게 말한다

`rank.py` 는 **정답의 순위**만 본다. 모델이 무엇을 답으로 고르는지는 안 본다.
G09 9세션(`experiment-2026-08-14-answer.md`)의 최종답을 문자 비중과 대조하면:

```
  111715171   6회   비중 0.171   ← 필터가 뺀다 (베트남어 번역본)
  363013408   3회   비중 0.000
  285314444   2회   비중 0.000   ← 정답
  175931444   1회   비중 0.000
```

**모델이 절반의 세션에서 답으로 고른 문서가, 필터가 빼는 바로 그 문서다.**
그 문서의 정답 순위는 20위 → 15위로 5칸 올랐을 뿐이라 `rank.py` 에는 안 보인다 —
번역본이 정답보다 위에 있었고 모델은 위에서부터 읽으므로, **후보 목록에서 사라지는
것과 순위가 5칸 오르는 것은 모델에게 전혀 다른 사건이다.**

## 결론

- **랭킹 지표로는 값어치를 증명하지 못한다.** 30질의에서 상위 10 적중이 안 변했다.
- **오염 제거로는 증명된다.** G09 에서 모델을 6/12 회 틀리게 만든 문서가 제외된다.
- **따라서 이 필터의 판정 기준은 `rank.py` 가 아니라 에이전트 벤치다.** 다음에 잴
  때는 G09 를 필터 켠 볼트로 다시 돌려 적중 1/9 가 오르는지 본다($5 안팎).
- **기본값은 계속 꺼짐이다.** 이 코퍼스에서 켤 이유는 G09 하나이고, 켜면 473건이
  grep 에서도 사라진다. 다국어 코퍼스를 가진 사용자가 켜는 선택지로 남긴다.
