# WikiLens 아키텍처 벤치마크 결과

## 이 벤치마크가 답하는 것과 답하지 않는 것

**답하지 않음.** 실제 위키에서 이 설계가 효용이 있는가. 실사용 적중률이 얼마인가.
합성 코퍼스의 파라미터를 내가 정했으므로, 여기 나오는 적중률은 **내가 심어놓은 가정의
함수**일 뿐이다. 절대 수치를 인용하면 안 된다.

**답함.** 지금까지 단언한 주장들이 자기 모순 없이 성립하는가. 파라미터 민감도가 어떤가.
설계에 논리적 결함이 있는가.

결과적으로 **주장 하나가 틀렸고, 하나는 반증됐으며, 새 위험 하나를 찾았다.**

**설정.** 페이지 2,000개 · 어휘격차 44% · 평균 출력차수 12 · 주제상관 링크 27% ·
Zipf(α=1.1) 질의 6,000건 · 고유 정답 947개

## 요약

| 실험 | 주장 | 결과 |
|---|---|---|
| E1 | 앵커가 어휘 격차를 메운다 | **방향 확인** (격차 52% vs 비격차 14%) |
| E2 | 손익분기 = `1/n` | **틀림. 공식 수정** |
| E3 | RRF가 Wilson 신뢰도를 버려 손실 | **반증. 제안한 수정안이 더 나빴다** |
| E4 | L1 개선이 L2 문턱을 올린다 | **확인, 단 강도는 약함** |
| E5 | 비링크 도달 비율이 관건 | 91.5% — 이 설정에선 문제없음 |
| E6 | churn 민감도 | **새 위험 발견** — 커버리지 붕괴 |

## E2 — 손익분기 공식이 틀렸다

내가 말한 모델은 케이스가 둘이었다.

```
적중 -> 1 읽기,  실패 -> 1+n 읽기
E = p·1 + (1-p)(1+n)   =>   p > 1/n
```

실제로는 셋이다. **"숏컷이 없음"은 헛읽기 비용이 0인데 그걸 실패에 뭉갰다.**

```
적중        -> 1 읽기      p_hit
잘못된 숏컷 -> 1+n 읽기    p_wrong
숏컷 없음   -> n 읽기      p_none    <- 손해 없음
```

전개하면:

```
p_hit·1 + p_wrong(1+n) + p_none·n  <  n
=>  p_hit(n-1) > p_wrong

** 손익분기:  p_hit > p_wrong / (n-1) **
```

**절대 적중률이 기준이 아니라 적중 대 오답 비율이 기준이다.** 캐시가 확신 없을 때
답을 내놓지 않으면 `p_wrong → 0`이 되어 거의 항상 이득이다. 그리고 Wilson 게이트가
하는 일이 정확히 그것이다.

실측 검증 (n=3.32):

| Wilson 게이트 | p_hit | p_wrong | p_none | E[L2] | 공식 예측 | 실측 |
|---|---|---|---|---|---|---|
| 0.00 | 65.4% | 1.2% | 33.4% | 1.55 | 이득 | 이득 ✓ |
| 0.45 | 64.9% | 1.2% | 33.9% | 1.56 | 이득 | 이득 ✓ |
| 0.70 | 41.7% | 0.3% | 58.0% | 1.97 | 이득 | 이득 ✓ |

**이 정정은 설계에 유리하다.** 앞서 "20~55% 적중률이 필요하다"고 했던 문턱이
실제로는 훨씬 낮다. 침묵할 줄 아는 캐시는 손해를 보기 어렵다.

> 발견 경위: 0% 워밍업에서 E[L2]가 n보다 낮게 나오는 게 물리적으로 불가능해서 추적했다.
> 별개로 베이스라인 n을 고유 키 평균(2.01)으로 계산한 버그도 있었다 — Zipf 반복을
> 무시한 값이었고, 질의 가중 평균(1.82)이 맞다.

## E4 — 긴장은 실재하나 약하다

| L1 구성 | 평균 n |
|---|---|
| 본문 BM25만 | 6.04 |
| 본문 + 앵커 | 3.33 |
| 본문 + 앵커(2배 가중) | 3.24 |

수정된 공식에서 문턱은 `p_wrong/(n-1)`이므로 n이 6.04에서 3.33으로 줄면 문턱이
약 2.2배 오른다. 방향은 확인되지만, **`p_wrong`이 분자에 있어 게이트로 직접 통제 가능**
하므로 앞서 말한 만큼 치명적이지 않다. "L1을 잘 만들면 L2가 죽는다"는 과장이었다.

## E3 — 제안한 수정안이 반증됐다

RRF가 Wilson 신뢰도를 버린다는 지적은 코드상 사실이다. 그러나 대안으로 제시한
확률 부스트(`RRF × (1 + α·reliability)`)는 **오히려 3.3% 나빴다** (1.895 → 1.957).

신뢰도를 정답 확률과 일치시켜 생성했으므로 조건은 최대한 유리했는데도 졌다. 결론:
구현이 조악했거나, 이 구성에서 신뢰도의 한계 정보량이 순위 정보에 이미 담겨 있거나.
**억지로 튜닝해서 살리지 않았다.** 현 시점 판정은 "제안 기각".

## E6 — 새 위험: Zipf 집중이 양날이다

앞 60%로 워밍업 → churn 적용 → 나머지 40%를 기록 없이 측정. churn은 인기 가중
(실제 위키에서 인기 페이지가 더 자주 수정되므로).

| 변경 페이지 비율 | 서빙율 | 적중률 |
|---|---|---|
| 0% | **45.5%** | 98.3% |
| 5% | **7.0%** | 94.6% |
| 15% | 2.2% | 94.3% |
| 35% | 0.3% | 100.0% |
| 60% | 0.0% | — |

**페이지 5%가 바뀌자 커버리지가 85% 사라진다.** 정확도는 유지되므로 위험하진 않지만
쓸모가 없어진다.

원인은 구조적이다 — 캐시는 핫셋에 집중되고, churn도 핫셋에 집중된다. 캐시를 유용하게
만드는 바로 그 성질이 캐시를 취약하게 만든다.

**함의:** "구조 변경에만 반응하는 무효화"가 있으면 좋은 게 아니라 **필수**다. 오타 수정
하나로 무효화하면 캐시가 상시 빈 상태가 된다. 이건 앞서 부수적 항목으로 다뤘던 것인데
격상해야 한다.

## E1 / E5

**E1.** 어휘 격차 페이지에서 51.8% 개선, 비격차 페이지에서 13.9%. 앵커 가치가 격차에
집중된다는 예측대로다. 다만 **격차 크기를 내가 44%로 설정했으므로 크기는 무의미하다.**
실제 위키의 어휘 격차를 먼저 재야 이 수치가 뜻을 갖는다.

**E5.** 주제상관 링크 27%에서 비링크 도달 91.5%. 검색 직행 67.5%, 링크 1홉 1.4%,
2홉 7.1%. 이 설정에선 궤적이 링크 그래프를 재학습하는 문제가 없다.

단 **시뮬레이션 에이전트가 링크를 따라 이동하지 않고 랭킹만 읽는다.** 실제 에이전트는
링크를 따라가므로 이 수치는 낙관적일 가능성이 크다. E5는 여전히 실측이 필요하다.

## 설계 변경 권고

1. **`p_wrong`을 최우선 지표로.** 적중률이 아니다. Wilson 게이트를 낮춰 서빙을 늘리는
   것보다 오답을 줄이는 게 항상 낫다. `/api/stats`에 `p_wrong` 추가.
2. **구조 변경 감지를 필수 기능으로 격상.** 콘텐츠 해시 전체 비교는 캐시를 무력화한다.
   제목·섹션·링크집합만 해시.
3. **E3 수정안 폐기.** RRF 유지. 신뢰도 활용은 다른 방식을 찾거나 포기.
4. **원 페이저의 손익분기 서술 교체.** `1/n`은 틀렸다.
